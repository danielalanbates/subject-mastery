# The Web and Cloud Computing

Imagine you are standing in a vast, global library. You have a precise address for a specific book, which we discussed in our last lesson as the Domain Name System, or DNS. But once you arrive at the correct building, how do you actually ask the librarian for the information you want? This is the role of the Hypertext Transfer Protocol, or HTTP. When you type a web address into your browser, your computer sends a request message to the server that hosts that site.

Most browsers use a specific method called a get request to ask for a web page. This request follows a strict set of rules that tells the server exactly which page you want. In return, the server sends back a response message. This response includes a status code, such as two hundred, which indicates that the request was successful. Other codes, like the familiar four hundred four error, tell the browser that the requested page could not be found.

The standard HTTP protocol is straightforward, but it has a major weakness because it sends information in plain text. If someone were intercepting the data as it traveled across the wires, they could read your messages or see your passwords. To solve this, we use the Hypertext Transfer Protocol Secure, or HTTPS. This secure version does more than just encrypt the traffic. It also provides server authentication through digital certificates. These certificates act like a digital passport, proving that the server is who it claims to be. Before any data is exchanged, your browser and the web server perform a digital handshake to agree on a secret code. Once this code is established, all the information passing between you and the server is scrambled. Even if an eavesdropper manages to capture the packets, they would only see nonsense characters instead of your private data.

Because the web is designed to be stateless, each request you make is treated as if it were your very first one. The server does not naturally remember who you are or what you did a moment ago. To fix this, developers use cookies. A cookie is a tiny text file that the server sends to your browser to store on your local machine. Think of it like a claim ticket at a coat check. When you come back to the website, your browser hands that ticket back to the server. The server reads the information inside, recognizes your unique session, and knows exactly which items you left in your shopping cart or that you are already logged into your account.

Beyond individual websites, the architecture of the modern internet relies on cloud computing. In the early days, if a company wanted to host a website, they had to buy, plug in, and maintain their own physical servers in a closet or a dedicated room. Today, we rely on massive, centralized data centers owned by large service providers. Cloud computing allows companies to rent this computing power and storage space on demand. Instead of owning the hardware, a business simply pays to use a slice of a massive, shared infrastructure.

This model offers incredible flexibility. If a website suddenly experiences a surge in traffic, the owners can instantly rent more processing power from the cloud provider to handle the load. Once the traffic dies down, they release that power and stop paying for it. It is similar to renting a car for a long trip rather than buying a new vehicle every time you need to leave town. These data centers are filled with thousands of powerful computers connected by high-speed networks, all managed by sophisticated software that ensures your data is backed up and available whenever you need it.

While this centralized approach makes the internet faster and more resilient, it also changes how we think about security. When your data lives on someone else’s computer, you must trust that the provider is protecting it from unauthorized access and digital threats. As we move deeper into this interconnected world, understanding where your information is stored and how it is protected becomes essential. We have covered the infrastructure of the web and how we access it, but we must also consider the risks that come with these global connections. In our next lesson, we will explore the landscape of digital threats and the malicious software that aims to compromise these systems.

## Key ideas

- The Hypertext Transfer Protocol uses request methods like get and status codes to manage communication between web browsers and servers.
- The secure version of the protocol, HTTPS, protects data through encryption and uses digital certificates to verify the identity of the server.
- Cookies act as small, temporary identifiers stored on your device that allow web servers to maintain a session and remember user state.
- Cloud computing allows users and businesses to rent shared computing power and storage from massive, remote data centers rather than maintaining their own physical hardware.
- The shift toward cloud-based services provides immense scalability and efficiency, but it also centralizes data and necessitates robust security measures to prevent unauthorized access.
