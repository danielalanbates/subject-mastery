# Recursion

Imagine you are standing in a long line of people at a movie theater, and you want to know your position. You cannot see the front of the line, so you ask the person directly in front of you for their position. That person does not know, so they ask the person in front of them, and so on. This continues until the question reaches the very first person, who knows they are number one. That person tells the person behind them that they are number two. That person adds one and tells the person behind them they are number three. This message travels all the way back to you, adding one at each step, until the answer reaches your ears. You have just participated in a recursive process.

In computer science, recursion is a technique where a function solves a problem by calling itself to solve a smaller version of the same problem. While loops are the standard way to iterate through data, recursion offers an alternative way to think about complex tasks. Every recursive function requires two essential parts. The first is the base case, which is the simplest possible version of the problem that can be solved immediately without further calls. In our theater line, the base case was the first person who knew their position without asking anyone else. Without a base case, a function would call itself indefinitely, eventually exhausting the computer's memory.

The second part is the recursive step, where the function calls itself with a smaller input. Computers manage these calls using a structure called a call stack. Think of this like a physical stack of plates. When a function calls itself, the computer places a new plate on top of the stack, containing the information needed for that specific instance. The computer pauses the current work and focuses entirely on the new, smaller task. When that task reaches its base case and finishes, its result is sent back to the previous function, and its plate is removed from the stack. The computer then resumes the previous task, using the result it just received.

Recursion is not limited to simple sequences. We often use it for the Fibonacci sequence, where each number is the sum of the two preceding ones, or for navigating branching structures like file systems or tree data structures. When traversing a tree, a function might visit a node, then recursively visit its left child and its right child. This can happen in different orders, such as pre-order, in-order, or post-order, depending on when the node itself is processed. Sometimes, recursion is indirect, where function A calls function B, and function B calls function A.

While recursion is elegant, it carries overhead. Each call requires memory for the stack frame. If the recursion depth is too great, the program hits a stack limit, causing a stack overflow. In contrast, iteration typically uses less memory because it does not need to store multiple stack frames. However, some languages, particularly functional ones, support tail-call optimization. If the recursive call is the final action of the function, the compiler can reuse the current stack frame instead of creating a new one. This allows recursion to run with the efficiency of a loop.

Ultimately, any recursive algorithm can be transformed into an iterative one by using an explicit stack data structure to manage the state manually. Choosing between them often comes down to readability and the nature of the problem. Recursion is often clearer for problems with natural recursive definitions, like traversing trees or performing a binary search, where you repeatedly split a sorted list in half to find a target value. Understanding the trade-offs between stack depth, memory usage, and clarity is a fundamental skill for any computer scientist. As we advance, you will see how this logic of breaking large problems into smaller fragments is the secret behind the most efficient algorithms.

## Key ideas

- Recursion occurs when a function solves a problem by calling itself to perform a smaller, simpler version of the same task.
- Every recursive function must include a base case to provide a stopping point and prevent infinite execution.
- The computer uses a call stack to track recursive calls, though deep recursion can lead to stack overflow errors if memory limits are exceeded.
- Tail-call optimization allows some programming languages to execute specific recursive patterns with the memory efficiency of an iterative loop.
- Recursion and iteration are computationally equivalent, and complex recursive processes can be rewritten iteratively using an explicit stack.
