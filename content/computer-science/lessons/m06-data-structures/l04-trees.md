# Trees

Imagine you are looking at your computer screen, browsing through your personal files. You click on a folder named Documents, and inside, you see a folder for your university work, and perhaps another for your taxes. If you open the university folder, you might find sub-folders for each semester. This structure is not just a convenient way to organize your life; it is a fundamental architecture in computer science known as a tree. In our previous lesson, we looked at hash tables, which are excellent for finding items instantly if you know exactly what you are looking for. But when we need to represent data that has a natural hierarchy or a nested relationship, trees are the superior choice.

A tree is a collection of nodes, which are points where data is stored, connected by edges that show the relationship between them. At the very top sits the root node. Think of the root as the ancestor of every other piece of data in the structure. From this root, branches extend downward to child nodes. Each child can have its own children, creating a cascading hierarchy. If a node has no children, we call it a leaf, much like the leaves at the ends of branches on a biological tree. Unlike the physical world, however, computer scientists usually draw these trees upside down, with the root at the top and the leaves at the bottom.

One of the most common and useful types of trees is the binary search tree. In a binary tree, every node has at most two children, typically referred to as the left child and the right child. What makes this a search tree is a strict rule about how data is placed. For any given node, all the values in its left subtree must be smaller than the value in that node, and all the values in its right subtree must be larger. This simple rule turns a collection of data into a machine for sorting and searching.

To find a specific value in a binary search tree, you start at the root. You compare your target value to the current node. If your target is smaller, you move to the left child. If it is larger, you move to the right. In a balanced tree, you eliminate half of the remaining data with every single step. In the language of complexity, this is a logarithmic process, which we describe as big O of log n. It is the computational equivalent of playing a game where you guess a number between one and one hundred, and the computer tells you if your guess is too high or too low. You can find any number in that range in seven guesses or fewer.

However, the efficiency of a binary search tree depends entirely on how well it is built. If you insert numbers into the tree in a perfectly sorted order, you might end up with a structure that looks less like a branching tree and more like a long, straight line. In this scenario, every node only has a right child. You have essentially turned your tree into a linked list. Searching this lopsided, unbalanced tree is no longer fast; it becomes a linear process where you have to check every single node one by one. In the language of complexity, this worst-case scenario is described as big O of n. This is why we aim to keep a tree balanced. A balanced tree ensures that the depth of the left and right subtrees remains roughly equal, keeping the search time consistently short.

Beyond file systems and search trees, these structures appear everywhere in computing. Compilers use them to understand the grammar of programming languages, and web browsers use a variation called the document object model to represent the structure of a webpage. Whenever you see a nested list of comments on a website or a menu in a game, you are interacting with a tree. They provide a way to model reality, where one thing belongs to another, and that thing belongs to another still.

By organizing data in these hierarchies, we gain the ability to navigate complex information with grace and speed. We have moved from simple linear lists and hash-based lookups to structures that mirror the way we categorize the world around us. While trees excel at representing these static hierarchies, sometimes the relationships between data points are far more complex, with connections weaving back and forth in ways that a simple tree cannot capture. When every node can be connected to every other node without the rigid rules of parent and child, we move into the domain of networks and graphs.

## Key ideas

- A tree is a hierarchical data structure consisting of nodes connected by edges, starting from a single root node and branching out to leaves.
- Binary search trees organize data such that every left child is smaller than its parent and every right child is larger, allowing for efficient big O of log n search times when the tree is balanced.
- If a tree becomes unbalanced, the search efficiency degrades from logarithmic to linear, which is big O of n.
- Trees are used throughout computing to manage hierarchical data, such as file systems on a disk, the structure of web pages, and the syntax of programming languages.
