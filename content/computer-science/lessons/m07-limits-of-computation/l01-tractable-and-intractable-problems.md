# Tractable and Intractable Problems

Imagine you are planning a delivery route for a truck that needs to visit twenty different cities. You want to find the shortest possible path that visits every single city exactly once and then returns to the starting point. This sounds like a straightforward task, especially since we have already explored how graphs allow us to map out connections between locations. You might think you can just list all the possible routes, measure their distances, and pick the winner. But here is the catch: as you add more cities to your map, the number of possible routes grows at a staggering, mind-bending speed. This is the Traveling Salesperson Problem, and it serves as the perfect gateway into the limits of what computers can actually do.

In computer science, we classify problems based on how much time they require to solve as the input grows. We call a problem tractable if a computer can solve it in what we call polynomial time. Think of polynomial time as a scale where the work grows in a manageable way. If you double the number of items you are processing, the time taken might increase by a factor of four, or perhaps eight. While that is more work, the computer can still finish the job within a reasonable human timeframe. These are the problems we consider effectively solvable. We have efficient algorithms for sorting lists, searching databases, and routing internet traffic because these tasks fall into the category of polynomial time.

However, many other problems are intractable. These are tasks where the time needed to find an exact solution grows at a rate that is super-polynomial. In the case of the Traveling Salesperson Problem, the brute-force search requires checking every permutation of cities. The number of distinct tours for this problem is the factorial of one less than the number of cities, divided by two. With twenty cities, the number of possible paths is roughly sixty quadrillion. Even a supercomputer would need to run for an immense amount of time to check every single combination. Because the time required grows factorially, we say these problems are computationally intractable. They are not provably impossible to solve in principle, but they are impossible to solve in practice for large inputs because no polynomial-time algorithm is currently known for them.

It is vital to distinguish between a problem that is hard because we lack a clever algorithm and a problem that is considered intractable because no efficient solution has been discovered. Sometimes, we can find a shortcut that turns a slow, super-polynomial problem into a polynomial one. But for many problems, like the Traveling Salesperson Problem, no such shortcut has ever been found despite decades of intense research. While it has not been mathematically proven that no polynomial-time algorithm exists, the consensus among researchers is that these problems are inherently difficult.

When we talk about these boundaries, we often use the language of complexity classes. We use big O notation to describe the worst-case scenario for an algorithm's performance. When an algorithm runs in polynomial time, its big O complexity is something like n squared or n cubed, where n is the size of the input. When a problem is intractable, its best-known algorithm might have a complexity that grows factorially, often written as big O of n factorial. As n increases, that factorial growth becomes a wall that no amount of processing power can climb. The difference between a polynomial curve and a factorial curve is the difference between a task that finishes before your coffee gets cold and one that lasts longer than the age of the universe.

Understanding these limits changes how we approach software engineering. If you realize that your project requires solving an intractable problem, you must accept that finding an exact, perfect answer for a large set of data is likely out of reach. This realization forces us to pivot our strategy, moving away from the search for absolute perfection and toward methods that provide useful results within a reasonable timeframe.

## Key ideas

- Tractable problems are those that can be solved in polynomial time, meaning the computational effort grows at a manageable rate as the input size increases.
- Intractable problems are those for which no polynomial-time algorithm is known, meaning the required effort grows at a super-polynomial rate that makes them infeasible for large inputs.
- The brute-force search for the Traveling Salesperson Problem runs in factorial time, which grows significantly faster than exponential time as the number of cities increases.
- A problem is considered intractable if the best-known algorithm requires super-polynomial time, though this does not mean a faster solution is mathematically proven to be impossible.
