# Whole Numbers and Overflow

Imagine you are using a digital odometer in a car that only has space for three digits. As you drive, the numbers climb from nine hundred ninety-eight to nine hundred ninety-nine. But what happens when you travel one more mile? The device cannot display one thousand, because there is no fourth slot. Instead, it resets to zero, zero, zero. This sudden shift from a large number back to the smallest possible value is not just a quirk of mechanical counters; it is a fundamental reality of computing known as overflow.

In our previous lesson, we explored how binary digits, or bits, represent values. We saw that any number can be expressed as a string of ones and zeros. However, a computer does not have an infinite amount of space. Every piece of data is stored in a container with a fixed size, usually eight, sixteen, thirty-two, or sixty-four bits. If you have only eight bits to work with, the largest number you can represent as an unsigned value is two hundred fifty-five. More generally, with n bits, you can represent unsigned values from zero up to two to the power of n, minus one. If you try to add one to the maximum value, the computer lacks the room to carry the one into a ninth bit. The result wraps around, causing the value to plummet back to zero. This is exactly like our three-digit odometer.

This limitation has real-world consequences. If a program is calculating something critical, like the speed of an aircraft or the balance in a bank account, an unexpected reset can be catastrophic. History is filled with examples of software bugs caused by this phenomenon. In some cases, a system designed to track time in milliseconds has overflowed after a specific number of days, causing the software to crash because it suddenly thinks the current time is decades in the past or far into the future. Engineers must carefully choose the size of their data containers to ensure they can hold the largest possible value the program might ever encounter.

Of course, we also need to represent negative numbers. You might wonder how a system built on simple switches that are either on or off can account for the concept of less than zero. We solve this using a system called two's complement. In this approach, we use a fixed number of bits to represent both positive and negative integers. With n bits in two's complement, we can represent values ranging from negative two to the power of n minus one, up to two to the power of n minus one, minus one.

The leftmost bit acts as the sign indicator. If the sign bit is zero, the number is positive. If it is one, the number is negative. To turn a positive number into its negative counterpart using two's complement, we follow a simple two-step process. First, we flip every bit in the number, changing every zero to a one and every one to a zero. This is called taking the inverse. Second, we add one to that result. Let us look at a four-bit example. Suppose we have the number three, which is zero, zero, one, one. To make it negative, we first flip the bits to get one, one, zero, zero. Then, we add one, resulting in one, one, zero, one. That final pattern is how the computer stores negative three.

Two's complement is clever because it allows the computer to perform subtraction using the same hardware it uses for addition. When the processor adds a positive number to a negative one, the math works out perfectly without requiring a separate subtraction circuit. The overflow we discussed earlier also applies here. If you add two large positive numbers and the result is too big for the sign bit, the computer might mistakenly interpret the result as a negative number because the sign bit was flipped by the carry-over. This is a common source of logic errors in software.

Understanding how we pack whole numbers into these rigid bit-sized boxes is the first step toward managing memory efficiently. It explains why a programmer must be intentional about the data types they use. We have mastered the representation of integers, but the world is rarely made of whole numbers alone. We often need to represent portions of a whole, like the decimal points in a price or the precise measurements of a scientific calculation. In our next lesson, we will explore how we expand these binary concepts to handle fractions and floating-point numbers.

## Key ideas

- A fixed number of bits creates a hard limit on the range of numbers a computer can represent, leading to overflow when a value exceeds that capacity.
- For unsigned integers, n bits represent values from zero to two to the power of n minus one, while two's complement allows for a range from negative two to the power of n minus one to two to the power of n minus one minus one.
- Overflow acts like a counter resetting to zero, which can cause significant software bugs if the program is not designed to handle the wrap-around.
- Two's complement is a standard method for storing negative numbers by using the leftmost bit as a sign indicator and applying a specific bit-flipping and incrementing process.
- Because computers use fixed-size containers, developers must choose the appropriate amount of memory for their variables to prevent errors during arithmetic operations.
